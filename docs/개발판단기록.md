# 개발 판단 기록

## 설계 기준
- 청구 접수 즉시 판정이 아니라, 기본 자료가 확보된 뒤 담당자가 검토할 순서를 제안한다. 변수의 실제 수집 시점이 제공되지 않아 운영 전 가용성 검증이 필요하다.
- 지급액·처리시간 자료가 없어 금액 절감이나 시간 단축을 추정 성과로 제시하지 않는다.
- AP(average precision)를 PR-AUC 대표 지표로 명시하고 상위 20% 포집률과 함께 본다.
- 고정 난수 계층 분할을 개발/검증/최종평가로 나누고 검증세트에서 모델·임계값을 선택한다. 최종평가는 선정에 쓰지 않는다.
- 식별자·인구통계·사후 확정 가능 변수는 보수적으로 제외한다. 실제 업무 누수 여부를 완전히 보장할 수는 없다.
- RAG 생성 단계는 필수로 두지 않는다. 공식 문서의 확인된 발췌를 로컬 검색해 출처와 함께 표시한다.

## 환경 오류 및 해결
- 내장 Python 3.13 래퍼의 PYTHONHOME 의존성 때문에 일반 venv 실행 시 encodings 모듈을 찾지 못했다. 시스템 Python의 독립 가상환경으로 전환하여 작업을 분리했다. 패키지 설치와 실제 테스트 결과는 별도 기록한다.

## 실행 환경 복구
- 시스템 Python 3.9 가상환경에서 NumPy 네이티브 모듈이 처음 누락되어 강제 재설치했다. 이후 브라우저에서 상속된 macOS quarantine 속성으로 라이브러리 로딩이 차단된 것을 확인했다. 프로젝트 가상환경의 설치 라이브러리 범위에만 런타임 준비 절차를 적용한 뒤 numpy/pandas/scikit-learn/CatBoost/SHAP/Streamlit import를 검증했다.
- Python 3.13 대안 환경도 구성했으나 실험과 최종 테스트는 독립된 시스템 Python 3.9.6 환경으로 통일했다. 일반 실행 방법은 특정 Aside 경로에 의존하지 않는다.

## 첫 비교와 모델 선택
- 검증 AP는 로지스틱 회귀 C=0.1이 가장 높았다. CatBoost를 사용하기 위해 더 낮은 성능 모델로 교체하지 않았다.
- 최종평가를 본 뒤 모델 파라미터·임계값·입력 열을 성능 목적으로 조정하지 않았다. 독립 코드 검토 후 같은 설정으로 재실행해 감사 정보와 설명 산출물만 보완했다.
- 실험 결과를 보고 튜닝하지 않는 운영 원칙은 있으나 최종평가 파일의 물리적 접근 차단이나 덮어쓰기 방지는 구현하지 않았다. 단일 고정 분할 결과이며 대규모 최적화 결과가 아니다.

## 독립 검토 후 수정
- 상수 점수의 고정 동점 순위 결과를 무작위 기대값으로 부르던 명칭을 바로잡았다. 무작위 검토의 수학적 기대값은 별도로 기록했다.
- 상위 8개 SHAP만으로 전체 점수를 재구성할 수 없으므로 나머지 기여도 합을 별도 저장하고 저장 산출물에서 가산성과 sigmoid 점수 일치를 검사했다.
- 제외 목록 방식에서 승인된 19개 입력 열 허용 목록으로 전환했다. 새 열이나 필수 열 누락 시 학습을 중단한다.
- 실제 모델 입력이 동일한 행과 분할 간 공유를 추가 감사했다. 고객/사건 ID가 없어 같은 입력을 중복 사고로 단정하거나 무조건 그룹화하지 않았다.
- 개발용 EDA는 학습세트 9252건으로 제한했다. 전체 행의 품질·분포와 학습 EDA의 모집단을 분리했다.
- 연도 스트레스 실험은 원 모델 선정에 마지막 연도의 일부 라벨이 포함된 한계가 있다. 독립 미래검증으로 표현하지 않는다.
- UI의 age 부분문자열 차단이 차량 연식과 AgentType까지 숨기는 문제를 정확한 인구통계 열명 차단으로 수정하고 회귀 테스트를 추가했다.

## GitHub 상태
- hyollim/claimpilot 전용 공개 저장소를 만들었다. 다른 저장소와 계정 전체 권한은 수정하지 않았다.
- 로컬 feature/claimpilot-mvp 브랜치에서 기능별 한국어 커밋을 기록했다. HTTPS Git 자격증명이 없어 push가 거부되었다. 인증 승인 전까지 원격 반영은 미완료이며 main 변경·병합·배포는 하지 않았다.

## GitHub 인증 문제 해결
- 사용자 승인 후 전용 저장소 1개에만 Contents/Workflows 쓰기, Metadata 읽기 권한을 가진 만료형 인증을 만들었다. 계정 권한을 추가하지 않았다. 비밀값은 Vault에 보관하고 코드·문서·로그에 남기지 않았다.
- 이 환경의 키체인 저장과 인증 보조 스크립트 실행 제한으로 Git 설정이나 원격 URL에 비밀값을 저장하지 않는 일회성 HTTPS 인증으로 전환했다. 사용 후 임시 인증 파일을 삭제했다.
- feature/claimpilot-mvp push를 완료하고 원격/로컬 커밋 일치를 확인했다. 최초 저장소에 main 브랜치를 생성하거나 병합·강제 push하지 않았다.

## 2차 개발: 기존 결과와 신규 입력의 경계
- 기준 커밋29d8b09의 모델·평가를 유지하고 reports/baseline_mvp 및 이전 포트폴리오 사본을 보존했다. 신규 입력에는 정답 라벨을 받지 않는다.
- 최초 시간평가 구현에서 미래 입력과 겹치는 과거22행을 제외한 실험을 수행했다(AP0.076508). 미래 자료를 보고 과거 선정 모집단을 바꾸지 않는 요구를 더 명확하게 지키려고 이 방식을 핵심 결과로 채택하지 않고 순수 연도 cutoff로 수정했다. 최종 시간평가는 과거11,337행 전부 사용, AP0.073166이다. 초기 참고 수치를 최종 성능으로 사용하지 않는다.
- UI 메뉴 변경 후 기존 테스트의 탭 위치 참조가 실패했다. 기존 검토·저장·검색 검증을 없애지 않고 새5개 메뉴 경로로 옮겨 재검증했다.
- 예산 CSV의 기본 CRLF가 git 공백 검사에 걸려 생성기의 줄바꿈을 LF로 고정했다.
- 독립 검토 후 정수 검사의 float 반올림 문제, nullable/categorical 입력, SHAP NaN 검사 누락, 배치 전환 필터 공유를 보완했다. 누적 배치 한도는 초과 저장을 거부하는 방식으로 구현해 기존 기록을 지우지 않는다.
- 배치 필터 회귀 테스트의 첫 버전은 메뉴에서 떠난 위젯 상태까지 유지될 것으로 가정했다. Streamlit이 숨겨진 위젯 상태를 정리하는 실제 동작을 확인한 뒤, 메뉴를 떠나지 않은 채 배치만 바꾸는 문제 경로로 테스트를 수정했다. 기대 동작은 다른 배치로 검색 조건이 새지 않는 것이며 필터 영구 보존이 아니다.
- BM25의 기준0은 후보 회수에는 유리하나 범위 밖 질문도 반환했다. 개발 자료에서 고른 기준24는 오탐을 줄이는 대신 평가 Recall@3이0.3333으로 낮아졌다. 평가 결과를 보고 새 임계값을 조정하지 않고 기존 키워드 검색을 기본으로 유지했다.
- 신규 공식 본문 후보6개는 재이용 허락을 확인하지 못해 공개 대상에서 제외했다. 기존8개 발췌를 보존하고 자체 작성 원문 경로3개만 별도 색인에 추가했다. 제한된PDF는 수집하지 않았다.
- class_weight 없는 모델과 보정 실험의 Brier가 더 낮아도 기존 test를 관측한 진단 결과로 생산 모델을 재선정하지 않았다. 새 추론 점수는 계속 비보정 모델 점수로 표시한다.
