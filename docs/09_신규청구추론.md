# 신규 청구 CSV 분석

## 입력 계약
- UTF-8 CSV, 5 MiB·5,000행 이하. 열은 claim_id와 기존 모델 입력 19개로 고정한다. 순서는 무관하다.
- 상세 열과 학습 범주는 [upload_schema.json](../resources/upload_schema.json)을 따른다.
- claim_id는 영문/숫자로 시작하는 1~64자 영문·숫자·밑줄·하이픈·마침표 조합이다. 배치 안 중복·누락은 거부한다.
- WeekOfMonth/WeekOfMonthClaimed는 1~5 정수, Deductible은 0 이상 정수다. 이는 입력 스키마 검사이며 보험 업무 규정이 아니다.
- 필수 열이 없거나 허용 밖 열(정답 라벨 포함)이 있으면 배치를 거부한다. 열은 있지만 값이 비었으면 __MISSING__으로 바꾸고 경고한다. 모든 입력값이 없는 행은 거부한다.
- 미관측 범주는 경고 후 기존 encoder의 handle_unknown=ignore 경로로 처리한다. 누락·미관측이 있는 건은 자료 보완 필요로 표시한다. 점수를 신뢰도나 실제 사기 확률로 바꾸어 해석하지 않는다.

## 모델과 기록 분리
기존 models/selected.joblib은 변경하지 않는다. prepare_inference.py가 기존 학습 분할 9,252행의 범주와 배경 평균만 추론 번들에 추가한다. test/validation을 SHAP 배경으로 쓰지 않는다. 외부 모델 파일 업로드는 지원하지 않는다.

새 배치는 입력 내용과 모델 버전 해시로 구분한다. 검토 기록 키는 new:배치ID:청구ID이며 기존 평가 데이터의 숫자 ID와 충돌하지 않는다. 같은 내용·모델의 재업로드는 기존 배치와 기록을 보존한다. 입력 순서나 내용이 달라지면 별도 배치가 된다. 배치와 설명은 로컬 data/intake.sqlite3, 상태·메모·체크리스트는 기존 review DB에 저장하며 git에서 제외한다. 다중 사용자 운영·암호화·개인정보 관리 체계가 아니므로 실제 개인정보를 넣지 않는다.

## 실행
```bash
python scripts/prepare_inference.py
python scripts/score_claims.py resources/demo_claims.csv --synthetic
```

[demo_claims.csv](../resources/demo_claims.csv)는 코드가 범주값을 조합하여 만든 합성 시연 6건이다. 실제 청구가 아니며 변수 조합의 업무 타당성을 보장하지 않는다. 1개 미관측 범주와 2개 누락값을 의도적으로 포함한다. 정답 라벨을 만들지 않았고 성능 평가에 사용하지 않는다.

SHAP는 기준값+상위8개 기여도+나머지 합=raw log-odds를 검산한다. 양의 기여도는 점수 상승 방향일 뿐 사기 증거가 아니다. 원본 자료를 확인한 담당자가 최종 사기 여부와 지급 여부를 판단한다.

## 경계 조건 보완
- 숫자는 Decimal로 정수성과 범위를 확인한다. CSV의 작은 소수 부분이 float 반올림으로 사라져 잘못 통과하지 않도록 했다. 직접 DataFrame 입력의 nullable 정수·범주 dtype도 object로 정규화한다.
- SHAP 배경 평균·기여도·기준값·raw 점수에 비유한 값이 있으면 합계 검사 전에 분석을 중단한다.
- 배치 저장은 최대50개 또는 JSON payload50MiB로 제한한다. 동일 배치 재조회는 허용하며 초과 시 새 저장을 거부한다. 기존 자료를 자동 삭제하지 않는다. 파일별5MiB와 DB 누적 한도는 서로 다른 제한이다.
- 검토 필터는 배치별 위젯 키로 분리한다. 다른 배치의 검색어 때문에 정상 배치가 빈 목록처럼 표시되지 않도록 전환 경로를 검사했다.
