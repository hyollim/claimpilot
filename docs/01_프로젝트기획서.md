# 01. 프로젝트 기획서

## 목적과 사용자
단일 담당자가 확보된 청구 자료를 점수 순으로 살펴보고, 모델 기여도와 원본 자료를 대조한 뒤 검토 이력을 남기는 로컬 실험이다. 지급·사기 자동판정은 범위 밖이다. 현재 대기열은 실제 접수 데이터가 아니라 공개 데이터 최종 test 3,084건이다.

## 구현 범위
1. 데이터 다운로드·감사 → 학습/검증/test 분리 → 모델·임계값 선정.
2. 점수 대기열·필터·청구 상세와 SHAP 표시.
3. SQLite 상태·메모·체크리스트 저장.
4. 공식 출처 발췌 8개 로컬 검색과 원문 링크 표시.

## 평가 기준과 현재 값
검증 AP 최대 모델을 선택하고 동률이면 상위 20% 포집률을 사용한다. 임계값은 검증 F1 최대값이다. test로 재선정하지 않는다.

선정 Logistic Regression C=0.1: AP 0.130255, Precision 0.104463, Recall 0.594595, F1 0.177706. 상위 20% 617건에서 양성 라벨 72/185건을 포집했다(포집률 38.92%, 정밀도 11.67%, 리프트 1.945315). 545건은 비사기 라벨(0)이며, 양성 113건은 상위 20% 밖에 남았다.

근거: [평가 결과](../reports/metrics.json), [선정 코드](../scripts/train.py).

## 범위 제한
- 학습 데이터 수집 지역·라벨 정의·실제 변수 수집 시점은 미검증이다. 한국 보험 업무 대표성을 주장하지 않는다.
- 인구통계·식별자·사후 판단 위험 변수 등 14열을 학습 입력에서 제외했지만 업무 누수 완전 배제를 보장하지 못한다.
- 인증·권한·다중 사용자 동시성·개인정보 보관/삭제/암호화·운영 감사체계는 미구현이다.
- 공식 검색은 전체 약관이나 RAG가 아니다. 개별 사건의 보장·과실·지급 판단을 생성하지 않는다.
- 지급액·작업시간 자료가 없으므로 비용절감·시간감소를 성과로 제시하지 않는다.

## 인수와 후속
구체적인 실행 검증은 [검증결과](검증결과.md)를 기준으로 하며 이 문서에서 테스트 총수·통과 완료를 확정하지 않는다. 현재 전달 범위 잔여 blocker는 GitHub HTTPS push 인증이다. 실운영 검증과 기능 확대는 [최종 결과](07_최종결과보고서.md)의 후속 항목으로 분리한다.
