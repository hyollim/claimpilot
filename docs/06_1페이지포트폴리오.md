# ClaimPilot | 자동차보험 청구 검토 순위 PoC

## 문제와 구현
담당자가 공개 데이터 청구를 어떤 순서로 확인할지 실험했다. Python·pandas·scikit-learn·CatBoost·SHAP·Streamlit·SQLite로 데이터 점검, 모델 비교, 순위/설명 조회, 상태·메모·체크리스트 저장을 구현했다. 현재 대기열은 공개 데이터 test 3,084건의 사전 계산 결과다.

## 설계 판단
- 15,420행·33열 중 19개를 범주 입력으로 사용하고 식별자·인구통계·판단시점 불명 변수 등을 제외했다.
- 학습/검증/test를 60/20/20으로 분리하고 검증 AP로 모델, 검증 F1로 임계값을 고정했다.
- 공식 자료는 확인된 발췌8개만 로컬 어휘 검색한다. 모델 SHAP와 분리하며 전체 약관/RAG로 표시하지 않는다.

## 실제 결과
Logistic Regression C=0.1: test AP **0.130255**, Precision **0.104463**, Recall **0.594595**, F1 **0.177706**. 상위20% **617건** 중 양성 **72/185건**(포집률38.92%, 정밀도11.67%). **545건은 비사기 라벨**, 양성 **113건은 미포집**이다.

고정 예측 bootstrap 95% 구간은 AP0.101728~0.171554, 포집률32.09~44.58%, 상위20% 정밀도9.24~14.10%다. 1996년 연도 스트레스 AP는0.073166, 포집률23.94%다. 1996년 일부 라벨이 원 모델 선정에 포함되어 독립 미래검증은 아니다.

## 한계와 전달 상태
점수는 사기 확률이 아니다. 원본 수집지역·라벨 정의·변수 수집시점이 미검증이며 한국 업무 성능·비용·시간 효과를 측정하지 않았다. 개발-test 공통 입력그룹19개가 남아 독립성 한계가 있다. 단일 담당자 로컬 PoC로 인증·동시성·개인정보 운영은 미구현이다. 최종 사기·지급 판단은 담당자가 수행한다. GitHub 저장소만 생성했고 HTTPS push는 인증 부재로 blocked다.
