# ClaimPilot | 청구 검토 순위를 어디까지 믿을 수 있나

## 문제와 실행
공개 자동차보험 청구에서 담당자의 검토 순서를 제안하는 로컬 PoC를 만들었다. 사기·보험금 지급을 자동 판정하지 않는다. 15,420행·33열, 양성923건을 점검하고 승인 입력19개로 모델을 비교했다. 기존 test 시연을 보존한 채 신규 CSV 추론과 배치별 검토를 추가했다.

## 입력에서 검토까지
- 업무 현황, 청구 데이터 분석, 청구 상세 검토, 모델 성능 및 업무 효과, 공식 업무 참고자료의 다섯 메뉴를 연결했다.
- UTF-8 CSV 5 MiB·5,000행·20열을 제한하고 누락 열·라벨·ID 중복은 거부한다. 값 누락·미관측 범주는 경고하고 자료 보완 대상으로 남긴다. 형식 확인을 진위나 사기 신뢰도로 표시하지 않는다.
- 자체 생성한 신뢰 가능한 로컬 joblib만 로드한다. SHAP 배경은 학습9,252행만 사용한다. 기여도 합을 검산하되 점수 상승 요인을 사기 증거나 인과관계로 설명하지 않는다.
- SQLite의 batch_id와 new:배치ID:청구ID 키로 원 평가 기록을 격리하고 같은 입력·모델의 재업로드는 검토 기록을 유지한다. 상태·메모·체크리스트 저장까지 연결했다.

## 결과와 수정한 판단
선정 LR C=0.1의 원본 test3,084건 AP는0.130255다. 상위20%617건에서72/185건, 38.92%를 포집했다. 함께 검토하는545건은 비사기 라벨이고 양성113건은 남는다. 5/10/15/20/30/40% 예산을 실측해 검토량과 포집·정밀도의 관계를 보여주되 비용절감으로 환산하지 않았다.

동일 입력 그룹을 격리하자 AP0.144584·포집44.51%였다. 그러나 같은 입력은 같은 고객·사건이 아니며 표본이 달라 향상으로 주장하지 않는다. 시간 검증에서는 미래 입력을 보고 과거22행을 제거하던 초기 설계를 폐기했다. 1994~1995년 전체로 선정하고1996년을 평가한 결과는 AP0.0731656·포집23.94%다. 1996년은 이번 선정에 쓰지 않았지만 MVP에서 이미 관측해 외부 미래 unseen 검증이 아니다.

순위와 확률도 분리했다. calibration1542행과 selection1542행을 따로 두고 보정했다. raw_none의 Brier0.054121이 raw_balanced0.215615보다 낮았지만 test 진단 후 추론 모델을 교체하지 않았다. 임계값 선정 표본이 달라 연구 F1과 원본 F1도 구분한다. 현재 점수는 비보정 값이며 실제 사기 확률이 아니다.

## 검색 실패와 전달 한계
기존 발췌8개를 보존하고 본문 권리 허락이 없는 신규 자료는 경로 안내3개만 더했다. 총11레코드, 신규 원문URL은KB2개다. 신규 후보 본문과 제한 PDF를 공개 색인에 수집하지 않았다. 기존8개 자율 수작업 질의 평가에서 BM25 기준0은 Recall@3 1.0이나 범위 밖2/2도 반환했다. 개발선정 기준24는 범위 밖0/2 대신 Recall@3 0.3333으로 낮아져 키워드를 기본 유지했다. 외부 gold·LLM·RAG는 없다.

원본 라벨 기준·수집시점, 한국 실무 성능은 미검증이다. 실제 비용·시간 절감과 운영 준비 완료를 주장하지 않는다. 실제 개인정보 입력, 다중 사용자 운영은 범위 밖이다. 기준29d8b09와 원보고서를 보존하며 main 병합·배포는 하지 않았다. UI·독립 리뷰·최종 원격 CI와 테스트 총수는 [2차 검증결과](15_2차검증결과.md), 수치 근거는 [모델 검증](11_2차모델검증보고서.md)·[검색 평가](13_검색평가보고서.md)를 따른다.
