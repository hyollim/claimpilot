# 04. 시스템 설계서

## 구성과 흐름
`scripts/download_data.py → data/raw/fraud_oracle.csv → scripts/train.py → models/selected.joblib + reports/* → app.py`

학습 스크립트가 test 점수·순위·개별 설명·집계 평가를 파일로 저장한다. 현재 앱은 사전 계산된 test 산출물을 읽으며 실시간 신규 청구 추론 API나 모델 재학습 서비스를 제공하지 않는다.

| 구성 | 책임/저장 |
|---|---|
| [modeling.py](../claimpilot/modeling.py) | 입력 제외, 문자열 범주 처리, AP·임계값·상위20% 평가 |
| [train.py](../scripts/train.py) | 분할·모델 비교·SHAP·부트스트랩·연도 스트레스 |
| [app.py](../app.py) | 청구 검토/성능 평가/공식 출처 검색 탭 |
| [review.py](../claimpilot/review.py) | SQLite data/reviews.sqlite3, claim_id별 상태·메모·체크리스트·UTC 수정시각 |
| [search.py](../claimpilot/search.py) | 로컬 발췌 어휘 일치 점수화, 외부 네트워크/생성 API 없음 |

## 검토 화면과 저장
청구 ID·우선순위 구간·검토 상태·점수 범위로 필터링하고 순위별 목록과 상세를 표시한다. 점수는 확률로 표기하지 않는다. SHAP는 raw log-odds 검토 단서이며 원인·사기 증거가 아니다.

저장 상태는 미검토/검토중/추가자료 요청/검토완료다. 메모는 최대4,000자, 체크리스트는 최대30항목이며 SQL 파라미터 바인딩과 트랜잭션으로 저장한다. 체크리스트 생략 시 기존 값을 유지한다. 저장은 운영용 감사로그나 다중 사용자 충돌 제어를 의미하지 않는다.

검토 화면에서 라벨·인구통계 관련 필드를 제거하고 평가 탭에서 정답을 표시한다. 이름 기반 필터는 보안·개인정보 통제의 대체물이 아니다. UI의 한국어 변수명은 원본 확정 데이터 사전이 아니며 [잠정 변수 해석](08_변수정의.md)을 따른다.

## 파일 계약과 실패 처리
- metrics.json: 후보/선정 모델, 분할, 임계값, 불확실성·스트레스 집계.
- data_audit.json: 행·열·중복·코드 이상·해시 점검.
- scored_claims.csv: test 원본열과 claim_id/risk_score/priority_rank/review_band/label.
- explanations.json: claim_id별 기준값/raw값/상위8개 변수 기여도와 나머지 기여도 합.
- 필수 산출물 누락은 준비 절차 안내, 빈 파일·필수열/청구ID/숫자 오류는 로드 중단, 설명 부재는 설명 없음으로 표시한다.

## 공식 발췌 검색
[official_sources.json](../resources/official_sources.json)의 8개 발췌를 제목·기관·절·본문의 가중 어휘 일치로 검색한다. 각 결과에 기관·제목·위치·확인일·원문URL·제한을 표시한다. 전체 약관/RAG가 아니며 답변 생성과 모델 판단 근거 결합을 하지 않는다. 최신성·이용조건은 외부 적용 전에 원문 재확인이 필요하다.

## 운영 경계
단일 담당자 로컬 PoC다. 인증·권한·동시성 제어·개인정보 암호화/보관/삭제·변경불가 감사·백업복구·서비스 모니터링은 미구현이다. 실제 개인정보를 입력하지 않는다. 원본 데이터·모델·검토DB·개별 청구 점수/설명·분할명세는 .gitignore 제외 설정했으며 커밋 추적 목록에서도 해당 파일들이 제외된 것을 확인했다. 실행 검증: [검증결과](검증결과.md).
