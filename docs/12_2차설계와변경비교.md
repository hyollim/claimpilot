# 2차 설계와 변경 비교

## 변경의 출발점
MVP는 공개 데이터 test의 사전 계산 점수와 설명을 조회하는 검토 도구였다. 이를 실제 신규 입력 추론과 혼동하지 않도록 입력·평가·검토 기록의 경계를 나누는 데 2차 작업의 중심을 두었다. 기준 커밋 29d8b09, reports/baseline_mvp와 기존 원보고서는 보존한다.

## 유지한 것과 추가한 것
|영역|유지|2차 추가·변경|
|---|---|---|
|학습·선정|기존 train 파이프라인, selected.joblib, 원 metrics|추론 번들 준비를 별도 명령으로 분리|
|검토|점수·SHAP 조회, 상태·메모·체크리스트|기존 test와 신규 배치를 선택하고 기록 격리|
|평가|원본 무작위 분할 지표|예산6비율·그룹·연도·가중치·보정 연구|
|공식자료|기존 발췌8개와 키워드 검색|자체 작성 경로3개, 선택형 BM25 비교|
|화면|원 검토·평가 기능|다섯 업무 메뉴와 CSV 분석 흐름|

코드 기준은 app.py, claimpilot/ui_phase2.py, inference.py, validation.py, calibration.py, retrieval.py다. 구현과 테스트의 최종 확인 범위는 [2차 검증결과](15_2차검증결과.md)를 따른다.

## 1. 화면을 업무 흐름으로 나누기
- **업무 현황**: 선택 자료의 미검토·검토중/추가자료·완료 집계, 점수순 10건과 분석/상세 이동.
- **청구 데이터 분석**: 스키마 확인 → 사용자 CSV 또는 합성6건 선택 → 입력 검사 → 로컬 저장 모델 추론 → 배치 저장 → CSV 다운로드/상세 이동.
- **청구 상세 검토**: 필터·건 선택 → 원자료와 SHAP 대조 → 상태·메모·체크리스트 저장. 정답·인구통계 열은 검토 표시 경로에서 제외한다.
- **모델 성능 및 업무 효과**: 기존 라벨 test만으로 예산표·누적 포집, 분할 비교와 보정 진단. 사이드바에서 신규 배치를 골라도 그 배치의 성과로 바꾸지 않는다.
- **공식 업무 참고자료**: 키워드 기본, BM25 후보(기준0), BM25 보수적 연구(기준24). 검색점수와 모델점수를 연결하지 않는다.

사이드바의 1~100% 우선 검토 비율은 ceil(n×비율) 순위 구간과 고정 test 분석에 적용한다. 비율을 바꿔도 저장 모델을 다시 학습하거나 사기 판정 임계값으로 쓰지 않는다.

## 2. CSV 계약은 추론 이전에 검사
UTF-8 CSV, 최대 **5 MiB·5,000행**, claim_id+19개 승인 모델 입력의 **20열**이다. 순서는 무관하나 필수 열 누락·추가 열·라벨 열·중복 열은 거부한다. ID는 영문/숫자 시작 1~64자 영문·숫자·_.- 조합이며 배치 내 중복·누락을 거부한다.

WeekOfMonth/WeekOfMonthClaimed는 1~5 정수, Deductible은 0 이상 정수다. 정수 검사는 Decimal로 수행해 부동소수 반올림으로 소수 입력이 정수로 통과하지 않게 한다. nullable/categorical DataFrame도 검사 전 object로 정규화한다. 이는 입력 형식 계약이지 실제 보험 규정의 검증이 아니다. 값 누락은 __MISSING__으로 표시하고 미관측 범주는 기존 handle_unknown=ignore 경로로 처리하며 경고한다. 모든 입력이 누락된 행은 거부한다. 경고가 있는 건은 자료 보완 필요로 남긴다. 형식 확인은 진위 확인이나 사기 위험 증거가 아니다.

사용자 자료는 진위 미확인, 합성 시연은 실제 청구 아님을 표시한다. 합성6건의 미관측 범주1개·누락값2개는 경고 시연용이다. 정답을 만들지 않았고 성능 평가에 쓰지 않는다. 다운로드는 수식 시작 문자열을 이스케이프하며 화면과 모델 원값은 바꾸지 않는다.

## 3. 모델 신뢰 경계와 설명
prepare_inference는 기존 selected.joblib을 바꾸지 않고 원본 체크섬과 기존 분할을 확인하여 추론 번들을 만든다. 학습 **9,252행**의 범주와 one-hot 평균만 사용하고 validation/test를 SHAP 배경으로 쓰지 않는다. joblib 로딩은 임의 코드 실행 위험이 있어 프로젝트에서 만든 신뢰 가능한 로컬 파일만 허용한다. 외부 모델 업로드 기능은 없다. 스키마 검사는 악성 joblib을 안전하게 만드는 보안 장치가 아니다.

신규 점수는 predict_proba의 비보정 값이다. 실제 사기 확률로 표시하지 않는다. SHAP는 기준값+상위8개 기여도+나머지 합이 raw log-odds와 일치하는지 검산한다. 배경 평균·기여도·기준값·raw 점수의 유한성도 검사한다. 양의 기여는 모델 점수를 올리는 방향일 뿐, 인과 효과나 실제 사기의 증거가 아니다.

## 4. SQLite 기록을 기존 test에서 격리
배치 ID는 모델 지문과 정규화된 입력 내용·순서의 해시로 구분한다. 신규 record_id는 **new:배치ID:청구ID**로 만들어 기존 평가 숫자 ID와 충돌하지 않게 한다. 내용/순서/모델이 바뀌면 다른 배치이며 같은 내용·모델 재업로드는 기존 배치의 이름·출처·기록을 덮어쓰지 않는다.

배치 점수·설명·검사 결과는 data/intake.sqlite3, 상태·메모·체크리스트는 data/reviews.sqlite3에 저장한다. 검토 화면의 필터 widget key도 배치별 namespace로 나눠 자료를 전환할 때 이전 선택값이 섞이지 않게 한다. 저장 한도는 50배치 또는 JSON payload 합계50 MiB다. 초과 시 신규 저장을 거부하고 기존 자료를 자동 삭제하지 않는다. 이는 DB 파일과 키의 논리적 분리이지 사용자 권한 격리·암호화가 아니다. 로컬 단일 사용자 전제이며 실제 개인정보를 넣지 않는다. 데이터·모델·DB·개별 점수와 설명은 git 제외 대상이다.

## 5. 추가 연구가 운영 모델을 바꾸지 않도록 분리
- analyze_budget: 기존 test 점수의 검토량별 포집을 계산. 무라벨 입력의 성과나 비용효과로 전용하지 않는다.
- validate_phase2: 19입력 그룹 격리와 순수 연도 cutoff를 별도 평가. 1996 입력으로 과거 모집단을 purge하던 초기 설계는 폐기하고 과거 전체를 유지했다.
- calibrate_phase2: 원 validation을 calibration1542/selection1542로 분리. test 진단에서 raw_none Brier가 좋아도 production 재선정·교체는 하지 않는다.
- evaluate_retrieval: 새 경로 항목을 섞지 않고 기존8개 발췌만 고정 평가. 평가 결과를 본 뒤 파라미터를 재선정하지 않는다.

그룹 격리의 44.51%와 순수 연도 평가의 23.94%는 분할군이 달라 향상·하락의 인과 효과가 아니다. 1996년은 이번 선정에서만 격리됐고 프로젝트 전체 unseen이 아니다. [모델 검증](11_2차모델검증보고서.md)에 수치와 한계를 적었다.

## 6. 검색 범위와 권리 판단
기존 발췌8개는 보존하고 신규 원문 경로 안내3개만 더해 UI 색인11레코드로 구성했다. KB 신규 원문 URL은2개이며 협회 경로는 기존 URL이다. 신규 후보6개 본문은 이용허락을 확보하지 못해 공개 색인에 넣지 않았고 후보 JSON은 git에서 제외했다. 제한된 PDF를 수집하지 않았다. 경로 안내는 권리 허락 완료나 규정 전문 수집을 뜻하지 않는다.

BM25의 높은 회수율만으로 기본 검색을 바꾸지 않았다. 범위 밖 질의 반환 문제가 남아 키워드를 유지했다. 결과가 없으면 관련 발췌 없음으로 안내하며 답변을 생성하지 않는다. LLM·임베딩·RAG는 없다. [검색 평가](13_검색평가보고서.md)에서 회수율과 false positive를 함께 보고한다.

## 남은 검증
원본 수집지역·라벨 판정 기준·입력의 실제 수집시점, 고객/사건 독립성은 미검증이다. 한국 실무 비용·시간 절감이나 운영 준비 완료를 주장하지 않는다. UI와 독립 리뷰 보완, 원격 전체 반영·최종 CI 확인은 [2차 검증결과](15_2차검증결과.md)에서 확정한다. main 병합·배포는 하지 않았다.
